### Задание 4 **(2)**

*Рассмотрим следующий пример в IDLE Python*

```
>>> x = 99.99
>>> int(x/10+0.001)
9
```

*Результат должен был быть равен 10, однако оказался другим. Почему так произошло?
Как исправить программу, чтобы она корректно переводила вещественные числа в целые?*

### Объяснение причины

Вещественные числа (тип `float`) хранятся в памяти компьютера в двоичном формате. Из-за этого десятичные дроби (такие как `99.99` или `0.001`) невозможно представить в виде конечной двоичной дроби абсолютно точно. Они превращаются в бесконечные периодические дроби и округляются с минимальной погрешностью.

Когда мы выполняем операцию `x / 10 + 0.001`, эти микроскопические погрешности складываются. В итоге в памяти компьютера вместо точного значения `10.0` получается число, которое чуть-чуть меньше: например, `9.999999999999998`.

Функция `int()` в Python не умеет округлять числа по математическим правилам. Её единственная задача — грубо отрезать (отбросить) всю дробную часть вещественного числа. Из-за этого число `9.9999...` превращается строго в `9`.

---

### Исправление программы

Чтобы программа корректно переводила вещественные числа в целые с учетом возможных математических погрешностей, вместо функции `int()` необходимо использовать функцию округления до ближайшего целого — `round()`. 

Правильный вариант кода:
```python
x = 99.99
result = round(x / 10 + 0.001)
print(result)  # Выведет правильный ответ: 10
```

### Задание 5. **(2)**

*Рассмотрите следующую программу. Объясните результаты ее работы. В частности,
как величина* $y$ *повлияла на ответ?*

```
x = 1/3
y = 1
for i in range(20):
    print((x+y)-y)
    y*=10
```

*В отчете требуется привести вычисления для оценки погрешности.*

### Объяснение результатов работы

В теории математики выражение `(x + y) - y` всегда должно быть строго равно `x`, то есть `1/3` (или `0.3333333333333333...`), независимо от того, чему равен `y`. 

Однако на практике при запуске программы мы увидим, что с каждой итерацией цикла ответ начинает искажаться. Сначала в последних знаках появляется «мусор», затем значащих троек после запятой становится всё меньше, а примерно на 16-17 шаге программа начнет выводить чистый `0.0`.

---

### Как величина y повлияла на ответ (Оценка погрешности)

В Python вещественные числа типа `float` занимают 64 бита, где под мантиссу выделено ровно **52 бита** (это дает примерно 15–17 точных значащих цифр в десятичной системе).

Когда мы складываем числа `x` и `y`, компьютер выполняет денормализацию — он подгоняет порядок меньшего числа под порядок большего. При этом мантисса меньшего числа `x` сдвигается вправо, а её младшие разряды выходят за пределы 52-битной сетки и безвозвратно теряются (компьютер их просто отбрасывает).

#### Вычисления для оценки:
* На старте `y = 1`. Числа `x` и `y` сопоставимы по размеру. Относительная погрешность представления `1/3` минимальна и составляет около \(2^{-53} \approx 1.11 \times 10^{-16}\). Мы видим длинную строку из троек.
* В цикле `y` на каждом шаге увеличивается в 10 раз (`y *= 10`). 
* К 16-й итерации `y` становится равен \(10^{15}\). При сложении `x + y` (то есть \(10^{15} + 0.3333...\)) число `x` полностью уходит в разряды, которые лежат за пределами 15-16 значащих десятичных цифр, доступных для `float`. 
* Компьютер вынужден округлить результат суммы `x + y` до ближайшего представимого числа, которым оказывается в точности сам `y` (\(10^{15}\)).
* В итоге операция `(x + y) - y` превращается для процессора в `y - y`, что дает на выходе ровно `0.0`.

**Вывод:** Чем больше становится `y`, тем сильнее сдвигается мантисса `x` вправо при сложении, из-за чего компьютер по цепочке теряет разряд за разрядом, пока `x` полностью не превратится в ноль на фоне огромного `y`.


### Задание 6 **(2)**

*Для какого минимального значения* $n$ *программа на С++ выведет* **inf**? *Объясните
ответ.* *Что произойдет, если тип* **double** *заменить на* **long double**?

```
int n=...;
double s = pow(2, n);
std::cout << std::fixed << s << std::endl;
```

### Ответ на первый вопрос (для типа double)

Минимальное значение `n`, при котором программа выведет `inf` (бесконечность), равно **1024**.

#### Объяснение:
Для типа данных `double` в C++, под хранение порядка числа отводится ровно 11 бит. Это позволяет хранить истинные порядки (показатели степени двойки) в диапазоне от \(-1022\) до \(+1023\).

Максимально возможное конечное число, которое вообще можно закодировать в типе `double`, это число, у которого истинный порядок равен \(1023\), а мантисса забита всеми единицами:
\(MAX\_VALUE \approx 1.79769 \times 10^{308}\) (что примерно равно \(2^{1024} - 1\)).

Когда мы пытаемся вычислить `pow(2, 1024)`, истинный порядок результата должен стать равным \(1024\). Но число \(1024\) выходит за границы допустимого диапазона экспоненты для `double`. В этот момент происходит **арифметическое переполнение** (overflow). Согласно правилам стандарта, при переполнении порядка число автоматически превращается в специальное значение плюс бесконечности — **`inf`**.

Таким образом:
* При `n = 1023` число еще помещается в память и выводится как огромное конечное число.
* При `n = 1024` происходит переполнение, и программа выводит `inf`.

---

### Ответ на второй вопрос (для типа long double)

Если заменить тип данных `double` на `long double`, то при `n = 1024` программа **не выведет `inf`**, а напечатает точное число. Переполнение в `inf` произойдет гораздо позже — при минимальном значении `n = 16384`.

#### Объяснение:
Тип данных `long double` является машинно-зависимым. Большинство компиляторов реализуют `long double` как 80-битное расширенное число с плавающей точкой.

В этом 80-битном формате под хранение порядка отводится уже не 11 бит, а целых **15 бит**. Диапазон возможных истинных порядков значительно расширяется: максимальный поддерживаемый порядок двойки возрастает до \(+16383\), а максимальное число составляет порядка \(1.18 \times 10^{4932}\).

Поэтому:
* Число \(2^{1024}\) легко и без каких-либо проблем поместится в диапазон `long double`.
* Значение `inf` для `long double` появится только тогда, когда мы превысим новый предел, то есть при попытке возвести двойку в степень **16384** (`n = 16384`).


### Задание 7 **(2)**

*Допишите что-либо вместо многоточия программе на С++, чтобы программа при запуске выдавала ответ* **yes**.

```
double s = ...;
if (s != s)
  std::cout << "yes";
```

### Решение

Вместо многоточия нужно подставить специальное значение **`0.0/0.0`**.

Правильный вариант кода:
```cpp
double s = 0.0 / 0.0;
if (s != s)
    std::cout << "yes";
```

---

### Объяснение

Результат неопределенных математических операций (таких как деление нуля на ноль `0.0/0.0`, бесконечности на бесконечность или умножение бесконечности на ноль) превращается в специальное сигнальное значение **`NaN`** (Not a Number — «не число»).

У значения `NaN` есть уникальное свойство, жестко зафиксированное в логике процессоров: **`NaN` никогда не равен ни одному числу, включая самого себя**. 

Поэтому:
* Операция сравнения `s == s` вернет `false`.
* Проверка на неравенство `s != s` вернет `true`.

Благодаря этому условие в блоке `if` успешно сработает, и программа напечатает слово `yes`.

Минимальное натуральное число, которое теряет точность в `double`, это **\(2^{53} + 1\)** (или в десятичном виде: **9007199254740993**).

#### Объяснение:
В формате `double` мантисса содержит ровно 52 физических бита памяти. Вместе с одной скрытой лидирующей единицей, которую компьютер держит в уме, мы имеем сетку точности ровно в **53 бита**.

Это значит, что абсолютно любое целое число, которое в двоичной записи укладывается в 53 разряда, можно сохранить в `double` со стопроцентной точностью, без каких-либо округлений. 

Максимальное число, состоящее из 53 двоичных единиц — это число \(2^{53} - 1\).
Следующее число — это \(2^{53}\) (в двоичном виде это единица и 53 нуля, всего 54 разряда). Но так как на конце у него одни нули, его мантисса «чистая» (все значащие биты — нули), и оно тоже сохраняется идеально точно.

А вот число **\(2^{53} + 1\)** в двоичной записи выглядит как единица, 52 нуля и единица на конце:
`10000000...00000001` (всего 54 двоичных разряда).

Чтобы уложить его в 53-битную сетку точности `double`, процессор вынужден сдвинуть число вправо и выбросить самую последнюю единицу, округлив значение. В итоге число \(2^{53} + 1\) превращается в памяти компьютера обратно в \(2^{53}\). Возникает погрешность, равная единице.

### Ответ на второй вопрос (почему следующее за ним число выводится без погрешности)

Следующее число за ним — это **\(2^{53} + 2\)** (в десятичной системе: 9007199254740994).

В двоичной записи оно выглядит как:
`10000000...00000010` (на конце единица и ноль).

Поскольку это число четное, его самый младший значащий бит — это ноль. При сдвиге числа для упаковки в 53-битную мантиссу `double` этот последний ноль отбрасывается без какого-либо ущерба для значения (ведь отбрасывание нуля не меняет величину числа). Оставшаяся часть мантиссы полностью совпадает с сеткой. Поэтому число \(2^{53} + 2\) сохраняется и выводится компьютером абсолютно **без погрешности**.

В этом диапазоне (после \(2^{53}\)) компьютер из-за нехватки бит начинает «шагать» строго через один: все четные целые числа сохраняются точно, а все нечетные — округляются до четных и теряют точность.

### Задание 9 **(2)**

*Напишите программу для решения следующей задачи.*

*Даны четыре рациональных числа. (Рациональное число - это число вида*

двух первых чисел с суммой двух последних чисел. Программа должна выводить* $1$, $0$ *или* $-1$
*в зависимости от результатов сравнения. Решение можно проверить в проверяющей системе*
[http://olymp3.isu.ru/cgi-bin/new-client?contest_id=102](http://olymp3.isu.ru/cgi-bin/new-client?contest_id=102), *задача 03*.

### Текст программы (Python)

```python
import sys

def main():
    input_data = sys.stdin.read().split()
    if not input_data:
        return
    
    t = int(input_data[0])
    results = []
    
    idx = 1
    for _ in range(t):
        if idx + 7 >= len(input_data):
            break
            
        p1 = int(input_data[idx])
        q1 = int(input_data[idx+1])
        p2 = int(input_data[idx+2])
        q2 = int(input_data[idx+3])
        p3 = int(input_data[idx+4])
        q3 = int(input_data[idx+5])
        p4 = int(input_data[idx+6])
        q4 = int(input_data[idx+7])
        idx += 8
        
        num1 = p1 * q2 + p2 * q1
        den1 = q1 * q2
        
        num2 = p3 * q4 + p4 * q3
        den2 = q3 * q4
        
        left_side = num1 * den2
        right_side = num2 * den1
        
        if left_side > right_side:
            results.append("1")
        elif left_side == right_side:
            results.append("0")
        else:
            results.append("-1")
            
    print(" ".join(results))

if __name__ == '__main__':
    main()
```

### Объяснение алгоритма

Чтобы программа работала абсолютно точно на больших числах и не спотыкалась о погрешности типа с плавающей точкой (float), все вычисления переведены в целые числа:
1. Для каждого из `t` запросов считываются числители и знаменатели.
2. Суммы дробей вычисляются через приведение к общему знаменателю: \(\frac{p_1 q_2 + p_2 q_1}{q_1 q_2}\).
3. Сравнение полученных дробей заменяется точным сравнением целых чисел «крест-накрест»: числитель первой умножается на знаменатель второй и сравнивается с числителем второй, умноженным на знаменатель первой.
4. Все результаты сохраняются в список и выводятся одной строкой через пробел.
